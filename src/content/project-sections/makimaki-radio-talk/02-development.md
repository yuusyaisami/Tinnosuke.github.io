## UI 実装の焦点

Unity の新しい UI システムである **UI Toolkit** を使い、読みやすさと更新しやすさの両立を目指しました。  
従来の UI より柔軟に構造化できる一方で、実装パターンの情報がまだ少なく、検証コストは高めでした。

## 開発メモ

| 項目 | 内容 |
| --- | --- |
| UI 基盤 | UI Toolkit |
| 重点 | 選択肢の読みやすさ、会話導線、レイアウトの保守性 |
| 課題 | 情報不足による試行錯誤の多さ |

## 試したこと

- 会話ブロックと選択肢ブロックを分離し、更新範囲を明確にする
- レイアウトをスタイル側へ寄せて、調整コストを減らす
- 文量が増えても破綻しにくい UI の余白設計を意識する

> 新しい UI 基盤を採用すると、見た目の自由度だけでなく、学習コストと検証コストも同時に増えると実感しました。

## 画面更新のイメージ

```text
選択肢を表示
  -> 入力を受け取る
  -> ステータスを更新する
  -> 次のトーク内容を決定する
```

## この開発で得たこと

UI Toolkit を使ったことで、ゲーム UI をコンポーネントとして整理する感覚がかなり掴めました。  
今後は、単に画面を作るだけでなく、状態管理や再利用しやすい UI 設計まで含めて深掘りしたいと考えています。
